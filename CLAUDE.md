# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

All development entry points go through `test/run.sh`:

```bash
test/run.sh instantiate      # resolve and precompile the project env (first-time setup)
test/run.sh test             # full test suite (memory-capped via systemd, output → .fm/test.log)
test/run.sh file stft.jl     # run one test file (relative to test/, or absolute path)
test/run.sh docs             # build the Documenter site into docs/build
test/run.sh bench            # allocation / timing profile (output → .fm/bench.log)
test/run.sh oracle           # regenerate audioFlux Python fixtures in test/audioflux_files/
```

A single test file loads a temporary env with MAT, Plots, and Test available — this is the fastest iteration loop.

## Architecture

Audio911 is a pure-Julia, Float32-end-to-end audio feature extraction library. Its defining characteristic is an **immutable pipeline**: every stage is a struct built from the previous one, and all downstream stages are written against a common interface (`src/interface.jl`), not against concrete front-end types.

### Pipeline shape

```
AudioFile → Frames → [front end] → [filterbank] → [cepstrum / feature]
```

Front ends: `Stft`, `Cwt`, `Cqt`, `Pwt`, `St`/`Fst`, `Nsgt`, `Dwt`/`Wpt`/`Swt`  
Filterbanks: `LinSpec`, `MelSpec`, `BarkSpec`, `ErbSpec`  
Cepstra: `Mfcc`, `Gtcc`, `Delta`  
Features: spectral descriptors, `Chroma`, `Tonnetz`, `OnsetStrength`, `Hpss`, ...

Because every front end implements the same interface, a `MelSpec` or `Mfcc` built on top of a `Cwt` is identical in structure to one built on `Stft`.

### Abstract type hierarchy (`src/Audio911.jl`)

- `AbstractAudioFile` — loaded audio (`AudioFile`)
- `AbstractFrame` — framed time-domain signal (`Frames`)
- `AbstractFBank` — filterbank design (`FBank`)
- `AbstractAudioSpectrum` — any frame-rate feature:
  - `AbstractSpectrogram{T}` — front ends and filterbank outputs (bins × frames internally)
  - `AbstractCepstrum` — cepstral coefficients
  - `AbstractDelta` — temporal derivatives
  - `AbstractSpectral` — one-value-per-frame descriptors

### Internal vs public orientation

`get_spec(s)` is the **internal accessor** used by all downstream stages: always **bins × frames**.  
`get_data(s)` is the **public accessor** used by callers: `Stft` returns bins × frames, filterbank stages and cepstra return **frames × bands** (matching MATLAB conventions).  
Adding a new front end requires implementing `get_spec`; adding a new downstream stage should consume `get_spec`, never the concrete type.

### Source layout

```
src/
  Audio911.jl        module root, abstract types, exports, includes
  interface.jl       shared accessors: get_spec, get_times, get_parent, …
  frames.jl          Frames, preemphasis/deemphasis
  audio/             AudioFile, format detection, libsndfile / mpg123 loaders
  fft/               Stft, istft, FBank, LinSpec, MelSpec/BarkSpec/ErbSpec, Mfcc/Gtcc, Delta, spectral descriptors
  wavelet/           Cwt, synchrosqueezing (Wsst/Synsq), discrete wavelets (Dwt/Wpt/Swt)
  transforms/        Cqt, Pwt, St/Fst, Nsgt, Wvd/Cwd, EMD/HHT, Reassign
  features/          time-domain features, pitch, Chroma, Tonnetz, Onset, Hpss, af_features
  signal/            DSP utilities, time-stretch/pitch-shift/phase-vocoder, unit conversions
  classic/           NMF, HMM/Viterbi
  plots.jl           Plots.jl recipes (RecipesBase, zero dependency cost)
```

### Test fixtures

Tests that compare against MATLAB's `audioFeatureExtractor` load `.mat` files (via `MAT.jl`).  
Tests that compare against audioFlux load `.mat` files generated by `test/run.sh oracle`, which runs Python scripts in `test/audioflux_sources/` and writes fixtures to `test/audioflux_files/`.

### Key conventions

- Everything is Float32 through the pipeline; allocation tests in `test/allocations.jl` enforce this.
- Window functions are re-exported from `DSP.jl` (`hanning`, `hamming`, `rect`, …).
- Plots recipes live in `src/plots.jl` using `RecipesBase` only — importing Plots is never required at the library level.
- `Maybe{T} = Union{T, Nothing}` is the project-wide optional type alias.
